# Deepbrid Finder Browser Extension

Deepbrid's premium website Usenet Finder is not part of the official Deepbrid API. Deepbridge can use it through a paired browser extension.

This avoids copied cookies, copied cURL headers, Byparr-only flows, and server-side Cloudflare workarounds.

## How it works

1. Deepbridge creates a per-configuration bridge ID and secret.
2. You install the browser extension.
3. You log into Deepbrid in the same browser profile.
4. You open the pairing URL generated by the dashboard.
5. The extension pairs with only that configuration.
6. Oracle sends Finder jobs to that paired browser queue.
7. The browser performs the website Finder search from the logged-in Deepbrid tab.
8. Results return to the matching Deepbridge configuration.

Cookies and Google credentials stay in the browser.

## Install the MV2 extension

Use the MV2 release if your browser supports Manifest V2.

1. Download the MV2 zip from the GitHub release.
2. Extract it.
3. Open your browser extension page.
4. Enable developer mode.
5. Choose "Load unpacked".
6. Select the extracted `browser-extension-mv2` folder.

## Pair it

1. Open Deepbridge dashboard.
2. Enable Deepbrid Usenet Finder.
3. Enable Browser Extension Finder Bridge.
4. Generate the manifest URL.
5. Open the generated pairing URL in the same browser.
6. Keep a logged-in Deepbrid tab open.

Success looks like:

```text
Paired with Oracle: ready for Finder searches.
Authenticated Deepbrid tab detected.
```

## How configs do not mix

Each dashboard configuration gets its own random bridge ID and secret. The extension only answers jobs for the paired configuration. Other users' configurations have different bridge IDs and secrets.

## When to re-pair

Re-pair if:

- You regenerate the dashboard configuration.
- You clear browser extension storage.
- You reinstall the extension.
- The Oracle deployment was reset and the bridge state changed.
- The Deepbrid tab was closed or logged out.
